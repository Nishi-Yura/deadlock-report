## 2. 10件から取り出した共通ルール（全ページ必須）

1. **最初の画面でスコアが読める。** 大会名・日付 → 両チーム名とスコア → マップごとの勝敗 の順（VLR / HLTV / FotMob）。
2. **見出しは小さく、数字は大きく。** セクション見出しは小さい大文字ラベル。大きくするのはスコアと主要な数字だけ（VLR / FotMob）。
3. **色はデータにだけ使う。** 勝ち負けは文字色か細い帯で示す。装飾のための色・グラデーションは使わない（HLTV / Opta / F1）。
4. **ドラフトは順番付きで書く。** 「1. Leviathan BAN Ivy」のように、ピック・BAN の流れを順番で読ませる（HLTV）。
5. **ヒーローは絵で示す。** 名前だけのタグにしない。スコアボードの選手名の横にヒーローのアイコン（VLR / HLTV）。
6. **数値は等幅・右揃え。** `font-variant-numeric: tabular-nums`、K/D/A は区切りをそろえる。
7. **連番を前面に。** レポートは `#1, #2 …`、大会は `DLNS #65`（Pudding / F1）。
8. **目次は表。** 番号 / 日付 / 大会 / 地域 / 優勝 / スコア（Liquipedia / F1）。
9. **出典を必ず書く。** ページ末尾に、データ元と動画のリンク。

### 禁止事項（ユーザー指定）
- Inter フォント
- 紫のグラデーション（紫そのものもアクセントに使わない）
- 光るボタン（`box-shadow` の発光、ネオン）
- 1語だけイタリックにしたセリフ体の見出し
- 横一列に並んだ4枚の統計カード
- 加えて、前回のレポートで「AI っぽい」と判断したもの：全部を同じ白い角丸カードに入れる／①〜⑤の同じ形のカード／「このページに載せていないこと」のような予防線の節／勝ち青・負けオレンジの初期配色

### 確認
- 幅 375px で、横スクロールが出ない（表は表の中だけでスクロール）、余白 16px、タップ領域 44px 以上。
- ホバーは色か下線の変化だけ。拡大・発光はしない。
- ライト / ダークの両方で読める。

## 3. 確定した方向性：A. スコアシート

元にした参考：**VLR.gg の試合ページ**と **HLTV の試合ページ**。比較した B（ナイトシフト）・C（データ記事）は `mockups.html` に残してある。

### 色（トークン）
| 名前 | ライト | ダーク | 用途 |
|---|---|---|---|
| `--page` | `#cfcfcb` | `#161615` | ページの地（VLR の灰色） |
| `--panel` | `#ffffff` | `#222220` | 白いパネル |
| `--cell` | `#f1f1ef` | `#2c2c2a` | 表の数値セル・マップ帯 |
| `--ink` | `#2b2b2b` | `#e8e8e4` | 本文 |
| `--mute` | `#6b6b6b` | `#9a9a94` | ラベル・補足 |
| `--line` | `#ececec` | `#333331` | 区切り線 |
| `--link` | `#0a7cad` | `#5bb6dd` | リンク・選手名 |
| `--win` | `#237a35` | `#5cc275` | 勝ち（文字色・細い帯のみ） |
| `--lose` | `#c92a2a` | `#ef6b6b` | 負け（文字色のみ） |
| `--hi` | `#e3f1e5` | `#1f3a26` | そのマップの最多セルの背景 |

- 色はデータにだけ使う。勝ちは緑、負けは赤の**文字**で示し、塗りは「最多セル」と「ヒーロー勝敗の帯」だけ。
- パネルは**角丸なし・影なし・枠線なし**。灰色の地との明度差だけで区切る（VLR）。

### 文字
- 数字・スコア・チーム名：**Barlow Semi Condensed**（600 / 700）
- 本文・和文：**IBM Plex Sans JP**（400 / 500 / 700）
- 本文 13px、表 13px、ラベル 11px・太字・大文字・字間 .08em・`--mute`。スコアだけ 40px（375px 幅では 32px）。
- 数値は `tabular-nums`。

### 部品（shadcn/ui を上の色・文字で作り直して使う）
- **Tabs**：マップ切り替え。下線だけで選択を示す（VLR の Overview / Performance タブ）。
- **Table**：スコアボード。セルは `--cell` の箱を 3px 間隔で並べる（VLR）。勝ちチーム・負けチームで表を分ける（HLTV）。
- **ヒーロー名**：ヒーローアイコンにマウスを乗せるとブラウザの title で名前が出る（2026-11-28 に shadcn の Tooltip から変更。全ページで JS が重くなっていたため）。
- **Separator**：パネル内の区切り。
- アニメーションは **パネルの出現（0.3秒、下から 6px のフェードイン）** だけで、CSS で動かす（`index.css` の `.reveal`）。発光・拡大・跳ねる動きは使わない。`prefers-reduced-motion` では止める。2026-11-28 に Magic UI（motion ライブラリ）をやめた：スコアのカウントアップは「0:0」が見えることがあり、BlurFade は JS を 500KB 以上重くしていたため。

### レイアウト
- 中央カラム最大 760px、パネル間 12px、パネル内の左右 16px。
- 上から：パンくず（大会名・日付・レポート番号）→ シリーズのスコア → マップ別の勝敗帯 → マップのタブ（ドラフト＋マップ情報の2カラム、スコアボード）→ 大会全体の集計 → 試合の流れ → 持ち帰り → 出典。
- 375px では 2カラムを1カラムに、マップ帯を縦積みに。表は表の中だけで横スクロール。

## 4. 再調査（2026-11-28）：ページが増えてごちゃごちゃしてきたのを整理する

ヒーロー・傾向・チーム・選手・比べる・用語集・予定・パッチ・サイトの更新…と機能が増え、ページが読みにくくなった。
「情報は多いのに散らからないサイト」を基準に、前回とは別の10件を内蔵ブラウザで開いて撮影し、`getComputedStyle` で実測した。
スクリーンショットは `design-refs/2026-11-28/`（`00-current-*` は現状のこのサイト）。

### 4.0 今のサイトのどこが散らかっているか（`00-current-*.jpg`）
- **レポートのタブが3段**：地域・ステージのタブ → シリーズのタブ → Map のタブ。今どこを見ているか分からない。
- **見出しの強さがそろっていない**：11px 太字大文字ラベル、13px 本文、パネル内の小見出し、灰色の注記が同じ画面に4〜5種類混ざる。
- **説明文がグラフ・表の下に毎回つく**（ソウル差グラフの下の 11px の段落、ヒーロー勝敗の下の段落）。読む人の多くは数字だけ見たい。
- **トップページに6種類のブロック**（レポート / 次の大会 / レポートをまたいで見る / パッチまとめ / サイトの更新 / フッター）が同じ白パネルで並び、どれが主役か分からない。
- **ページ内リンクの行**（このページ：マップ別・ヒーローと BAN…）が見出しの下で折り返し、375px では2行になる。
- **上部バー**：375px でロゴ＋5項目＋検索がぎりぎり。

### 4.12 10件から取り出した「整理」のルール（今回追加。2章のルールに上乗せ）
1. **1ページにタブは1段だけ。** 地域・ステージはタブではなく、ページ上部のスコア行やセレクトで選ぶ（Sofascore / op.gg の反面）。
2. **最初の画面に出す種類は3つまで。** レポートなら「要約1行・シリーズのスコア・マップの勝敗」まで（tracker.gg の反面 / VALORANT）。
3. **見出しの強さは2〜3段に限る。** ページ見出し・セクション見出し・本文。11px の大文字ラベル・灰色注記を増やさない（BBC / FotMob）。
4. **説明文は既定で畳む。** グラフ・表の下の解説は「この数字の読み方」として畳み、開いた人だけ読む（FotMob の畳める見出し）。
5. **和文の本文は 15px・行間 1.7。** 表の数字は 14px のままでいい（スポーツナビの反面 / VALORANT 18px）。
6. **一覧は「左に日付・右に中身」。** パッチ・更新・レポートの一覧は日付を等幅・灰色で左に出す（Linear / GitHub）。
7. **勝ち負けは濃淡でも示せる。** 負けた側を灰色にすれば、緑・赤を減らせる（NBA）。
8. **メニューは4つまで。** 残りは「その他」やページ内に移す。375px では下部タブバーも検討（FotMob）。
9. **フィルタは必要な人が開く。** 常に並べない（bo3.gg の反面）。

## 5. 確定（2026-11-28）：たためる整理したスコアシート

A（整理したスコアシート）に、C の「見出しでたためるパネル」を足したもの。**3章の色トークンは変えない。** 変えるのは文字の大きさ・見出し・ナビ・ページの組み立て。

### 文字（3章の「文字」を置きかえる）
| 用途 | 大きさ / 太さ | 書体 |
|---|---|---|
| 本文（和文） | **15px** / 400、行間 1.7 | IBM Plex Sans JP |
| ページ見出し h1 | 20px（375px 幅は 18px）/ 700、行間 1.5 | IBM Plex Sans JP |
| パネル見出し h2（`Label`・`Fold` の見出し） | **16px** / 700、`--ink`、大文字・字間なし | IBM Plex Sans JP |
| 表の数字 | 14px（375px 幅は 13px）、`tabular-nums` | Barlow Semi Condensed |
| 補足・日付・表の列名 | 13px / 400、`--mute` | IBM Plex Sans JP |
| スコア | 40px（375px 幅は 32px）/ 700 | Barlow Semi Condensed |
- 見出しの段は **h1・h2・本文の3段だけ**。11px の大文字ラベル（`.lab`）はスコア下の「FINAL」と表の中だけに残し、パネル見出しには使わない。

### ナビ
- 上部バーはロゴ（＝レポート一覧）＋ **4項目**：ヒーロー / 傾向 / チーム・選手 / 比べる ＋ 検索。
- 用語集・RSS・パッチ・テーマ切り替えはフッター。

### たためるパネル（`Fold`）
- `<details>` を使う。見出し行は高さ 48px 以上、左に h2、その右に 13px `--mute` の「一言の要約」（例：「Billy 4-0」）、右端に「開く / 閉じる」。
- 開いた状態でも閉じた状態でも見出しの見た目は同じ。ホバーは `--cellhover` の背景だけ。
- **最初から開く**：スコア、ドラフト・マップ情報、スコアボード、持ち帰ること。
- **最初は閉じる**：勝ち上がり表、ソウル差の推移、ヒーロー別の勝敗、BAN、配信画面、出典。
- 表やグラフの下の説明文は `Note`（「この数字の読み方」）にたたむ。空の状態（「なし」）やエラーはたたまない。

### レポートページの組み立て
1. スコアのパネル：大会名・日付・#番号 の1行 → 見出し文 → シリーズのスコア → マップの勝敗帯。ページ内リンクの行はなくす。
2. **タブは1段だけ**：シリーズが2つ以上あるときは、タブの列の左端にシリーズの切り替え（セレクト）を置き、右に Map 1〜N のタブ。
3. マップ（ドラフト＋マップ情報 → スコアボード → たたんだソウル差・配信画面）。
4. 持ち帰ること（開いている）。
5. ヒーロー別の勝敗・BAN・出典（たたむ）。

### トップページ
- 種類は3つまで：**レポート一覧 → 次の大会 → パッチ・サイトの更新**（1つのパネルに、左に日付・右に中身）。
- 「レポートをまたいで見る」の案内はナビと重複するのでなくす。
